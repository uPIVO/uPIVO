# Локальный демостенд

Эта конфигурация предназначена для ветки `deploy/local-demo`. Она запускает отдельный Compose-проект `upivo-demo`, не меняя рабочее окружение `upivo`. Переносить настройки стенда в `main` не требуется.

## Настройка

В каталоге отдельного worktree выполните `cp .env.example .env`. Файл `.env` не хранится в Git. Задайте независимые случайные `POSTGRES_PASSWORD` и `AUTH_TOKEN_SECRET` (для секрета авторизации не менее 32 символов). Для генерации каждого значения можно использовать `openssl rand -hex 32`. Пароль БД должен быть пригоден для URL; шестнадцатеричное значение подходит.

Перенесите существующие `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION` без создания новой Telegram-сессии. Укажите отдельные ключи провайдеров с ограниченным бюджетом. Провайдеры summary, importance и relevance настраиваются независимо: одного ключа может быть недостаточно. Не копируйте весь рабочий `.env`: он может вернуть рабочие порты и подключения.

## Запуск

Запустите Docker Desktop, затем из каталога worktree:

```bash
docker compose config --quiet
docker compose up -d --build
```

Swagger: http://127.0.0.1:18000/docs. PostgreSQL и Redis доступны только локально на портах 15432 и 16379. Все эти порты можно изменить в `.env`. Внутри контейнеров API использует сервисы `postgres:5432` и `redis:6379`; изменения локальных DATABASE_URL и REDIS_URL это не переопределяют. Миграции применяются перед запуском API. Данные БД хранятся в отдельном volume проекта, а не в рабочей базе.

Автоматический сбор и автоматический платный AI по умолчанию выключены. Это не запрещает платные вызовы из ручных API-запросов и не является денежной квотой. После настройки ключей и бюджета включите `SCHEDULED_PIPELINE_ENABLED=true`; `SCHEDULED_PAID_AI_ENABLED=true` включайте только для согласованного автоматического AI. Фоновые процессы запускаются командой `docker compose --profile workers up -d --build`. После изменения `.env` пересоздайте затронутые сервисы через `up -d`, а не только `restart`.

## Публичная ссылка

Публикуйте API только после проверки локального запуска, авторизации и ограничений расходов. В отдельном терминале выполните `ngrok http 18000` (при другом APP_PORT замените порт). Для ngrok нужен настроенный аккаунт и authtoken; токен не хранится в репозитории. Открывайте выданный HTTPS-адрес с суффиксом `/docs`. Не публикуйте порты PostgreSQL и Redis.

Туннель не заменяет авторизацию и ограничение частоты запросов. В этой конфигурации новый rate limiter не добавлен. Публичная регистрация и ручные платные запросы требуют контроля нагрузки и бюджета. Бесплатный ngrok имеет квоты и может показывать страницу предупреждения перед Swagger. QR-код должен ссылаться на HTTPS-адрес `/docs`.

Компьютер, Docker и ngrok должны оставаться включёнными; сон компьютера прерывает доступ. Исходящие подключения к Telegram и моделям используют сеть компьютера или VPN, а не туннель ngrok. Доступность необходимо проверять в используемой сети.

## Остановка

Остановите ngrok через Ctrl+C и выполните `docker compose --profile workers down`. Данные БД сохранятся. Не добавляйте `-v`, если данные нужно сохранить. Старое окружение запускайте только из его собственного каталога с его конфигурацией.
