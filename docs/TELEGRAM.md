# Локальный сборщик Telegram

Это локальный коннектор Telegram и два режима запуска из консоли: просмотр публикаций без сохранения и сохранение публикаций с курсором в PostgreSQL. Сборщик не использует Celery или обработку ИИ.

## Проверка настроек Telegram

Настройки Telegram проверяются через Pydantic только при запуске генератора сессии или создании клиента коннектора. Для генератора достаточно TELEGRAM_API_ID и TELEGRAM_API_HASH; коннектору дополнительно нужна TELEGRAM_SESSION. Отсутствие этих значений не мешает запуску остального backend. Ошибки валидации не выводят секретные значения.

## Учётные данные и сессия

Каждый разработчик использует собственные учётные данные Telegram API. Получите `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` на [my.telegram.org](https://my.telegram.org) и добавьте их в корневой `.env` репозитория (сначала создайте его из `.env.example`). Не добавляйте эти значения в Git, не пересылайте их и не записывайте в логи. Файл `.env` исключён из Git.

Из каталога `backend/` создайте Telethon StringSession:

```bash
uv run python -m scripts.generate_telegram_session
```

Помощник запросит номер телефона, код входа Telegram и, если потребуется, пароль двухфакторной аутентификации. Он сохраняет StringSession непосредственно в существующий корневой `.env`, оставляет остальные настройки без изменений, ограничивает доступ к файлу владельцем там, где это поддерживается, и никогда не выводит сессию. Не передавайте сгенерированную сессию и не добавляйте её в Git: она равнозначна учётным данным аккаунта. Коннектор не начинает интерактивный вход — сначала создайте сессию.

После ввода номера помощник подсказывает, куда Telegram отправил код. Если указан
«чат Telegram», откройте проверенный служебный чат Telegram на любом устройстве,
где уже открыт этот аккаунт: SMS может не приходить. Номер вводите в международном
формате. Не запрашивайте код многократно подряд и никому его не пересылайте.

Если код не приходит, а Telegram уже открыт на телефоне, используйте вход по QR
из каталога `backend/`:

```bash
uv run python -m scripts.generate_telegram_session --qr
```

На телефоне откройте **Настройки → Устройства → Подключить устройство**, сканируйте
QR в терминале и подтвердите вход. Код действует недолго; помощник показывает
новый QR, если прежний истёк. При включённой двухфакторной защите он дополнительно
попросит пароль. QR-код даёт доступ к аккаунту, поэтому не пересылайте его и не
публикуйте снимки терминала. После подтверждения StringSession сохраняется в `.env`
так же, как при входе по коду.

## Список каналов аккаунта

После создания сессии выполните из каталога `backend/`:

```bash
uv run python -m scripts.list_telegram_channels
```

Команда выводит названия и полные ID всех публичных и приватных каналов из диалогов аккаунта, включая архивированные. Обычные группы и супергруппы не включаются. ID уже имеет формат Telethon (`-100…`); его можно передать коннектору без преобразования. Значения сессии и API-ключей не выводятся.

```bash
uv run python -m scripts.telegram_sync --limit 5 -- -1001234567890
```

Замените пример ID значением из списка. Разделитель `--` отделяет отрицательный ID от опций командной строки.

## Чтение публикаций канала

После установки зависимостей выполняйте команды из каталога `backend/`. Источником может быть имя канала (`@example` или `example`), URL канала (`https://t.me/example` или `https://t.me/s/example`), полный ID канала в формате Telethon, например `-1001234567890`, или приватная ссылка `https://t.me/c/<id>` на канал, участником которого уже является аккаунт.

По умолчанию начальная загрузка возвращает последние 50 логических публикаций; `--limit` задаёт их количество. Сообщения альбома считаются одной логической публикацией:

```bash
uv run python -m scripts.telegram_sync @example --limit 50
```

При передаче `--after-message-id` возвращаются все логические публикации строго после указанного ID. Если также передан `--limit N`, возвращаются первые N логических публикаций после этого ID в хронологическом порядке. Это позволяет читать следующие порции без пропуска публикаций. Альбом считается одной публикацией; поэтому N не задаёт точную верхнюю границу message ID. Без `--limit` инкрементальная загрузка не ограничена. Если курсор проходит внутри альбома, самый ранний возвращённый альбом дополняется обратным сканированием до предыдущей другой группы; поэтому его `message_ids` и подпись могут включать компоненты с ID не больше курсора, а `message_id` остаётся максимальным ID альбома. Консоль выводит наибольший возвращённый ID сообщения, который вызывающий код может сохранить отдельно; коннектор не хранит и не продвигает курсор.

```bash
uv run python -m scripts.telegram_sync @example --after-message-id 104 --limit 5
uv run python -m scripts.telegram_sync @example --after-message-id 104
```

Результаты выводятся в хронологическом порядке. У каждого `TelegramPost` есть стабильный `external_id` (`message:<id>` или `album:<grouped_id>`), максимальный `message_id` компонента, упорядоченный `message_ids`, время `published_at` с часовым поясом UTC, объединённый текст подписей, `grouped_id` и признак `is_forward`. Служебные сообщения пропускаются. Публикация с медиа без текста возвращается с `text=""` (в выводе отображается как `[textless post]`); медиа не скачивается, публикации не отправляются на обработку ИИ.

Доступны только каналы, которые может читать авторизованный аккаунт. Для приватного канала аккаунт уже должен быть участником. Если подписанный ID приватного канала отсутствует в кэше сущностей Telethon, коннектор проверяет уже доступные аккаунту диалоги; ссылки-приглашения не принимаются, запросы на вступление не выполняются. Ошибка разрешения канала или доступа сообщается без записи в лог исходного исключения Telegram, введённого источника, API hash, кода входа или сессии.

## Сохранение публикаций в PostgreSQL

Перед первым запуском примените миграции из каталога `backend/`:

```bash
uv run alembic upgrade head
```

Запустите сбор доступного канала:

```bash
uv run python -m scripts.collect_telegram @example
```

При первом запуске сохраняются последние 50 логических публикаций. При повторном запуске курсор читается из `telegram_sync_state`, и загружаются только публикации после последнего успешно сохранённого message ID. `--limit N` ограничивает количество логических публикаций. Посты записываются в `feed_items`; Telegram-метаданные — в `raw_payload` (JSONB). Посты и курсор сохраняются одной транзакцией. При ошибке нормализации или записи вся пачка откатывается, курсор не продвигается.

`scripts.telegram_sync` остаётся режимом просмотра без сохранения. Старые редактирования и удаления автоматически не обнаруживаются; перепроверка последних 10 сохранённых постов остаётся отдельным этапом. ИИ, расписание и Celery не запускаются.

Из каталога `backend/`:

```bash
pytest -q tests/test_telegram_credentials.py tests/test_telegram_connector.py tests/test_list_telegram_channels_cli.py tests/test_telegram_session.py tests/test_telegram_sync_cli.py tests/test_telegram_persistence.py tests/test_telegram_persistence_service.py tests/test_telegram_persistence_sql.py
```

В этих тестах используется фиктивный клиент Telegram и временные `.env`-файлы; запросы к Telegram не выполняются, файл `.env` разработчика не читается.
