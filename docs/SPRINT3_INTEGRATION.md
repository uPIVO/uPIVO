## Интеграционные исправления

- Разрешён конфликт Feed: сохранён общий предикат видимости из ITD-89 и добавлено
  ранжирование из `feed-digest-ranking`. Сохранены обе модели Feedback/Favorite.
- Все пользовательские API используют один проверяемый подписанный Bearer-токен
  регистрации. Удалены `X-User-Id`, числовые Bearer и JWT без проверки подписи.
  Лента/дайджесты проверяют принадлежность переданного user_id, избранное берёт ID

  Служебные Habr API тоже требуют авторизации.

  Ошибки входа не различают неизвестный email и неверный пароль.

  не переписывая старые revisions и данные.
- Ошибка персональной AI-оценки больше не возвращается как успешная задача:
  Celery делает до трёх повторов с задержкой, затем оставляет failed.
- Старые API-тесты используют подписанные тестовые токены; безопасность проверена
  отдельно обычным TestClient без обхода dependencies.
- PostgreSQL-тесты AI изолированы по базам: явные ID из одного теста больше
  не вызывают конфликт identity при повторном полном запуске.
- CI дополнен Redis, отдельными тестовыми БД и сквозными проверками;

## Ограничения

- Нет учёта просмотров: после изменения интересов прежние оценки инвалидируются,
  но массовый ретроспективный пересчёт пока пропускается; новый контент оценивается.
- Квитанция постановки не является outbox. Потеря сообщения брокером и исчерпание
  повторов требуют отдельной стратегии восстановления/мониторинга.
- Реакции сохраняются, но автоматически не обучают ранжирование.
- До публичного запуска нужны HTTPS, ограничение частоты регистрации/входа,
  политика отзыва токенов и контроль расходов AI. Жёсткой квоты AI сейчас нет.
- Для ручного входа в этой версии необходимо самостоятельно задать локальный
  `AUTH_TOKEN_SECRET`; пользовательский `.env` при интеграции не изменялся.

Тестовые контейнеры и копия БД удалены после проверок. Существующие контейнеры,
volumes и stash проекта сохранены. Commit, push и merge в `main` не выполнялись.
