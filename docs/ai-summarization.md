# Ручная суммаризация единиц контента

Этап 1 ITD-17 предоставляет контракт суммаризации, не зависящий от конкретного провайдера, и адаптер OpenRouter. Единица состоит из одной или нескольких нормализованных публикаций. Операция не читает и не изменяет базу данных, ORM-модели или `processing_status`.

## Настройка

Настройки читаются из корневого `.env` через `app.core.config.Settings`. Пример безопасных имён параметров находится в корневом `.env.example`:

- `LLM_PROVIDER=openrouter` — единственный провайдер, реализованный на этапе 1;
- `LLM_API_KEY` — секретный ключ OpenRouter; не добавляйте ключ в Git и не передавайте его в логи;
- `LLM_BASE_URL=https://openrouter.ai/api/v1` — базовый URL API, совместимого с OpenAI; допускается только HTTPS;
- `LLM_MODEL=@preset/deep-seek-v4-flash-via-direct-deep-seek-provider` — идентификатор пользовательского пресета OpenRouter, передаваемый параметром `model`; значение можно изменить настройкой;
- `LLM_TIMEOUT_SECONDS=60` — конечный таймаут запроса (допустимый диапазон: больше 0 и не более 300 секунд).

Ключ нужно задать только локально в `.env`; этот файл не редактируется автоматически. Для ручного запуска требуется явное решение владельца о реальном запросе: вызов может быть платным. Обычные тесты не обращаются к провайдеру.

## Запуск эксперимента

Из каталога `backend`:

~~~sh
uv run python -m app.ai ../docs/examples/content-unit.json --save-result /tmp/upivo-summary.json
~~~

Команда принимает один JSON-объект `ContentUnitInput`, не открывает БД и печатает выжимку, отпечаток версии, признак повторного использования, время выполнения и доступные сведения об использовании. Токены и стоимость выводятся только если их сообщил провайдер; оценочные значения не подставляются.

Для повторного запуска с теми же входом и настройками передайте ранее сохранённый файл:

~~~sh
uv run python -m app.ai ../docs/examples/content-unit.json \
  --prior-result /tmp/upivo-summary.json \
  --save-result /tmp/upivo-summary.json
~~~

При точном совпадении отпечатка версии можно повторно использовать непустую выжимку без сетевого вызова. Отпечаток включает сериализованный вход, идентификаторы провайдера, базовый URL, пресет и фактический текст инструкции; `PROMPT_VERSION` нужно повышать при изменении инструкции модели. Если изменились вход, провайдер, базовый URL, пресет или версия инструкции, результат генерируется заново. `--force` явно запрашивает новый результат. Файл результата — локальные данные, которым доверяет вызывающая сторона; командная строка проверяет его структуру, непустую выжимку и версию отпечатка. Секреты в отпечаток не входят.

Автоматических платных повторов и молчаливого усечения входа нет. Слишком длинный запрос может быть отклонён провайдером; ошибка не содержит тело ответа или исходный текст. Если `finish_reason` отсутствует, ответ допускается для совместимости; если поле присутствует, принимается только `stop`. Ответы с другой причиной завершения или встроенной ошибкой отклоняются, неполная выжимка не сохраняется как успешный результат.

## Контракт и границы

Публикации передаются адаптеру как JSON с фиксированными именами полей; `raw_payload` в DTO запрещён. Поля `body_text` и `original_url` обязательны и непусты. Остальные сведения, включая `title`, `published_at`, `source_name`, `extracted_entities` и `is_primary`, необязательны. Пустой список публикаций недопустим, одна публикация допустима. В инструкции модели указано считать текст публикаций недоверенными данными, суммировать все источники, сохранять существенные условия, имена и числа, не выдумывать факты и отмечать значимые расхождения. Персонализация не выполняется.

Повторное использование доступно только через явно переданный файл результата; скрытого процессного кэша нет. Долговременное хранение выжимок, загрузка кластеров, автоматическая инвалидация при изменении состава кластера, оценка персональной релевантности и общей важности, а также изменение статуса обработки отложены до последующих согласованных этапов.
